# Domain Guide

本文件記錄 SupportOptimizer 的核心工程概念與不應被 AI 自行改寫的 Domain Rules。完整細節仍以 `README.md`、既有程式與測試為準。

## 1. Problem Domain

本專案處理地下開挖支撐系統中的圍令（Waler）與支撐（Strut）材料配置。

目標不是單純把長度湊滿，而是在工程限制、材料規格、接頭位置與施工需求下，產生合法且較佳的配置方案。

## 2. Core Entities

### Waler（圍令）
沿開挖周邊配置的水平構件。

主要考量：
- 起終點與總長。
- 支撐、斜撐、角撐等造成的禁止接頭位置。
- 材料規格與可用長度。
- 接頭數、材料種類、短料比例與尾端調整。

### Strut（支撐）
跨越開挖區域、將荷載傳遞至圍令的橫向構件。

主要考量：
- 起終點與需求長度。
- 所屬分區（zoning）。
- 起終點圍令。
- 中間柱與托梁位置。
- Jack、Shim、餘量與材料配置。

### Brace（斜撐 / 角撐）
會影響圍令接頭禁止位置或支撐幾何關係的斜向構件。

### Inventory（材料庫存）
包含材料用途、規格、長度與數量。

材料是否可裁切、哪些長度可用，不可由 AI 任意假設；應依既有程式與專案資料。

## 3. Important Terms

### Segment / Steel Piece
組成圍令或支撐的標準鋼材片段。

### Joint
兩段鋼材的接頭位置。

接頭不能只考慮幾何可行，還需避開工程禁止區。

### Jack
支撐系統中用於調整與施力的元件。

Jack 的位置會參與單支支撐合法性與多支支撐全域協調，不應視為任意插入的固定長度元件。

### Shim / Adjustment Piece
用於微調長度的調整材料。

### Forbidden Zone / Forbidden Point
工程上不允許接頭、Jack 或特定構件落入的區域或位置。

來源可能包含：
- 支撐端點。
- 斜撐 / 角撐。
- 中間柱。
- 托梁。
- 其他幾何限制。

## 4. Waler Domain Rules

目前的重要規則包含：

- 圍令材料目前不可任意裁切。
- 每一段需對應可使用的材料長度。
- 接頭需避開禁止位置 / 禁止區。
- 方案評分除合法性外，還考量購買數、材料比例、短料、材料種類、料長差與接頭數等。
- 尾端允許的 adjustment / gap 必須依既有演算法常數與規則，不可自行放寬。

修改上述規則前需先閱讀：
- `docs/wales/README.md`
- `bracing_optimizer/algorithms/wales.py`
- 對應測試。

## 5. Support Domain Rules

支撐求解不是單根獨立最佳化後直接結束，而是兩階段問題：

1. 每支支撐產生多個合法候選。
2. 同分區內再進行多支支撐的全域配置。

重要規則包含：

- 每支支撐需滿足自身長度與禁止區限制。
- 中間柱與托梁會形成位置限制。
- Jack 位置與相鄰支撐之間存在協調需求。
- 雙路支撐仍是兩支實體支撐，但同一 Shared Layout Group 的 ordered pieces 必須一致。
- 材料比例、材料型態與候選多樣性會影響候選保留與全域搜尋。

修改這些規則時，不可只看單一函式；需同時檢查 candidate generation、cache key、global search 與 tests。

## 6. Geometry and Coordinates

本專案同時處理 CAD / DXF 世界座標與 GUI / 工程資料。

重要原則：
- CAD 端點位在寫入事件前會轉為 WCS。
- DXF 匯入與結果輸出應維持既有座標語意。
- 不可在沒有明確需求與測試的情況下改變 UCS/WCS、單位或投影方式。

## 7. Validation Is Domain Knowledge

以下不是單純 UI 驗證，而屬於工程資料品質的一部分：

- ID 空白或重複。
- 幾何座標無效。
- 線段長度 <= 0。
- 支撐與斜撐端點不在指定圍令上。
- 起終點圍令不合理。
- 支撐與圍令方向關係異常。
- 托梁、中間柱位置重複或超界。
- Inventory 規格、長度或數量無效。

新增或改變 validation 時應先判斷：這是 UI 輸入提示，還是工程 Domain Rule。

## 8. Source of Truth

若文件、程式與測試有衝突，依以下順序確認：

1. 現行需求 / 明確使用者決策。
2. 通過的回歸測試所表達的既有行為。
3. 現行程式實作。
4. `README.md` 與 `docs/`。

遇到衝突時應回報，不要自行選一個版本默默修改。
